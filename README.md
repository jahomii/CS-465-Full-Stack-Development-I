# CS-360-Mobile-Architect-and-Programming

**Architecture**

A traditional express HTML / Javascript site requires more work on the server to produce a functional webpage. While this standard format can be very useful for user analytics and a more intuitive experience, SPA pages perform better in terms of speed and memory use and create a more dynamic user experience. MongoDB's importance for the SPA structure comes into play when you consider its flexible schema and ability to store large amounts of unstructured data.

**Functionality**

Javascript is largely used for formatting and manipulating data while JSON is used particularly for transmitting data. They tie together in both the front and back-end development by creating a uniform structure that can organize, format, and then send specified amounts of data to and from the backend. One instance in which I refactored code to improve functionality was in the HTML script and TS files for the trip-listing / trip-data-service components. I could make calls to specific pieces of data such as current available trips, trip information, and log-in status. These calls would then act upon the data currently stored in the database without the need to go in and change it manually. This made the full-stack application more dynamic without the need to hardcode in these paths of information.

**Testing**

Methods are how the application should behave, including the tasks it is meant to perform and how it should do so. 
Endpoints are specific URLs in which the backend and frontend communicate with each other and transfer information.
Security is to ensure that the important details of your full-stack application such as your database and API access cannot be accessed by unauthorized individuals.
